# 株価テクニカル分析ツール

**「トヨタ」「ドル円」「ビットコイン」**のように日本語で入れると株価を取ってきて、
移動平均・ボリンジャー・一目均衡表・OSGFC・Lorentzian Classification などのテクニカル指標、
空売り残高、信用残、資金フロー、ニュースを1画面で見るツールです。
**PCとスマホのお気に入り・履歴は Google ドライブ経由で自動同期されます。**

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体(これ1つで動きます) |
| `worker.js` | 自分専用の中継サーバー(任意・置くと速く・私的になります) |
| `中継サーバーの作り方.md` | 上を置くための手順(5分) |
| `manifest.json` | ホーム画面に追加するための設定 |
| `sw.js` | オフラインで開くためのキャッシュ |
| `icon-192.png` / `icon-512.png` | アイコン |

**`worker.js` 以外の5つを同じ階層に置いてください。** サブフォルダに分けると動きません。

`index.html` だけをパソコンで直接開いても(`file://`)、指標も空売りデータもふつうに使えます。
そのときは Google ドライブ同期とオフライン機能だけが無効になり、
設定の持ち運びは「ファイルに書き出す」「コードをコピー」で行います。

## 置く場所

同期とオフラインを使うなら、どこかに **https で公開**する必要があります。
GitHub Pages / Netlify / Cloudflare Pages のいずれかにフォルダごとアップロードしてください。
無料の範囲で足ります。

## 同期の設定(初回だけ)

1. Google Cloud Console で OAuth クライアント(ウェブアプリケーション)を開く
2. **承認済みの JavaScript 生成元**に、公開したURLの生成元(例 `https://xxxx.github.io`)を追加する
   - ここを自分のドメインだけに絞ってください。空のままだと誰でもこのクライアントIDを使えます
3. OAuth 同意画面のスコープに `https://www.googleapis.com/auth/drive.appdata` を追加する
4. PC でアプリを開き、いちばん下の「PC ↔ スマホで共用」→「Googleドライブに接続」
5. スマホで同じURLを開き、同じ操作をする

**Orange Card と同じ生成元に置くなら、クライアントIDはそのまま使い回せます。**
`drive.appdata` はクライアント単位の隠しフォルダで、保存ファイル名が
(`orange-card-data.json` と `ta-tool-sync.json` で)違うため、記録が混ざることはありません。
別のIDを使いたいときは、画面の「準備と、うまくいかないとき」の中の欄に貼って「IDを保存」を押してください。

設定は Drive の「アプリ専用データ領域」に入ります。マイドライブには表示されず、
このアプリ以外からは読めません。ファイルを選ぶ操作は不要です。

同期のタイミングは、**アプリを開いたとき / ★を押したとき / 別のタブから戻ってきたとき**です
(戻ってきたときは前回から1分以上たっている場合だけ)。「今すぐ同期」でいつでも手動実行できます。

## 何を見られるか

入力欄に日本語で入れると候補が出ます。コードを覚えている必要はありません。

| 種類 | 入力例 |
|---|---|
| 日本株 | `トヨタ` `とよた` `ソニー` `ユニクロ` `三菱UFJ` `7203` `285A` — 主要597銘柄を内蔵(日経225 / JPX日経400 / 日経500)。2024年以降の英数字コード(`285A` など)も引けます |
| 海外株 | `AAPL` `MSFT` — ティッカーで |
| 為替 | `ドル円` `ユーロ円` `ポンド円` `豪ドル円` `ユーロドル` ほか15通貨ペア |
| 暗号資産 | `ビットコイン` `イーサリアム` `リップル` — 円建て/ドル建ての両方 |
| 商品 | `金` `原油` `銀` `プラチナ` `天然ガス` `銅` `小麦` ほか |
| 指数 | `日経平均` `S&P500` `ナスダック` `ダウ` `VIX` `ハンセン` ほか |
| 米国債利回り | `米10年債` `米30年債` `米5年債` `米13週` |
| ETF | `SPY` `QQQ` `VOO` `GLD` `TLT` / 国内なら `1306` `1321` `1540` ほか |

内蔵の表にない銘柄は、入力して「分析」を押すと Yahoo の検索にかけます(そのときだけ通信します)。

**投資信託(eMAXIS Slim など)は扱えません。** Yahoo Finance の米国APIが日本の公募投信を持っていないためです。
`2559`(全世界株ETF)や `1306`(TOPIX ETF)など、上場しているETFで代用してください。
**TOPIX指数そのものもYahooに無い**ため、`1306` を使っています。

## 中継サーバーを自分のものにする(おすすめ)

株価もニュースも、ブラウザから直接は取れません(CORS)。既定では無料の公開中継サーバーを
経由していますが、**混んでいると時間切れになり、見ている銘柄がその運営者に渡ります。**

同梱の `worker.js` を Cloudflare Workers に置くと、その両方が解決します。無料枠で足ります。

**パソコンの Chrome か Firefox で**行ってください(Cloudflareの編集画面はSafariでは動きません)。

1. アプリの「通信(中継サーバー)」→「worker.js を保存」(または同梱のファイルを開く)して全部コピー
2. https://workers.cloudflare.com/playground を開く
3. 左のコード欄を **Ctrl+A → Ctrl+V** で貼り替える
4. 右上の **Deploy**(初回はログインとサブドメイン登録を求められます)
5. 出てきた `https://….workers.dev` をアプリの欄に貼って「保存して確認」

詳しい手順は同梱の **中継サーバーの作り方.md** にあります。

中継してよい相手はコード内で7ホストに限定してあるので、URLを知られても
他人が別サイトへの踏み台に使うことはできません。
**転送(リダイレクト)先も1ホップずつ同じ判定にかけます** — 許可ホストが
別のサイトへ飛ばしてきても、そこには付いていきません。
`worker.js` の先頭にある `ALLOW_ORIGIN` を自分の公開URLにすると、さらに自分のページ専用になります。

**独自ドメインに置く場合**は、`index.html` の先頭付近にある `connect-src` にそのドメインを
足してください(`workers.dev` のURLならそのままで使えます)。アプリ側でも警告を出します。

## お気に入り一覧・アラート・シグナルの成績

- **空売り残高は「報告者ごとの最新報告の合計」**です。JPXの日次ファイルは
  *その日に提出された報告*であって残高一覧ではないため、単純に合計すると
  報告の無い日が0になり、合計も実際よりはるかに小さく出ます(v19以前はそうでした)。
  いまは報告者ごとに最新値を持ち越して合計しています。<br>
  **0.5%未満になると報告義務が消える**ので、そこから下は追跡できません。また、
  さかのぼる日数が少ないと以前から積まれている残高が抜けます。投資情報サイトの
  数字と揃えたいときは「半年分」以上を取得してください
- **残高を持ち越す単位は「報告義務者＋委託者」**です。同じ運用会社が複数の
  ファンドについて別々に報告することがあり、会社名だけで数えると後の行が前の行を
  上書きして合計が小さく出ます(v20以前はそうでした)。一覧では委託者も表示します
- **割合のスケールはファイル単位で判定**しています。JPXのファイルは割合を
  0.0292(＝2.92%)という小数で持ちセルの書式で%を付けているのですが、
  1セルだけを見ると「0.45」が *0.45%* なのか *45%* なのか決められません
  (0.5%を割った解消報告は実際に0.45のような値になります)。ファイル全体で
  %書式が1つでもあるか、全部の値が0.5未満か、で決めています。v20以前の版が
  保存したキャッシュも読み込み時に補正します
- **空売り残高は13ヶ月分**取れます。JPXが月別ページで公開しているので、
  「半年分」「1年分」で月別ページをたどって集めます。1日1ファイルなので1年分は約240件・数分かかります。
  取得済みの日付は飛ばすため、途中で止めて後日続けても構いません
- **決算発表予定日**はJPXの予定表から取れます(予定日のみ)。チャートに縦線が入ります。
  **過去の発表日と月次売上は扱っていません** — 無料で機械的に取れる出所が無いためです
- **信用残の1年分は取れません**。JPXの銘柄別はPDFのみ、日証金は当日スナップショットのみです
- **逆日歩(品貸料率)**は日本証券金融の当日の一覧(`shina.csv`)から取れます。
  出ないときは、その銘柄に逆日歩が付いていない(貸株が不足していない)か、貸借銘柄ではありません
- **日経のページ**(信用残の推移・逆日歩と貸借残・株主優待)へのリンクをカードに置いています。
  日経のサイトは `robots.txt` で自動取得を断っているので、**中身の取り込みはしていません**。
  リンクを押してご自身のブラウザで開く形にしてあります
- **お気に入り一覧** … ★の銘柄をまとめて取得し、現在値・前日比・RSI・25日線乖離・クロスを1つの表に。
  見出しを押すと並べ替え、行を押すとその銘柄を開きます
- **アラート** … 移動平均クロス / RSI / 価格で通知。**ページを開いている間だけ動きます**
  (サーバーを持たないため)。一度鳴ったら、条件から外れるまで鳴り続けません
- **このシグナルは効いているのか** … 各シグナルが過去に出たあと何本後にどうなったかを集計します。
  **「どの足でもいい適当な地点」から同じ期間を見た中央値と比べ**、それを超えていなければ
  そのシグナルはこの銘柄では何も見つけていません。10回未満の行は薄く表示します。
  いずれも手数料・スリッページ抜き、表示中の期間への後付けです

## 足種

`1分 / 5分 / 15分 / 30分 / 1時間 / 4時間 / 8時間 / 日足 / 週足 / 月足`

**4時間足と8時間足は提供元に存在しません。**1時間足をまとめて作っています。
そのことは見出しに「1時間足4本ぶんをまとめて作成」と表示します。
まとめる範囲は**同じ日の中だけ**で、日をまたぐ足は作りません
(東証は6時間立会なので、4時間足は1日あたり「4時間+2時間」の2本になります)。

## パネルの高さを変える

各パネルの**下の余白を上下にドラッグ**すると、そのパネルだけ高さが変わります。
ダブルクリックで元に戻ります。価格パネルも同じように変えられます。
高さは端末ごとに保存されます。

## 開いたときに自動で取れるもの

日本株を開くと、**空売り残高(直近10日)・信用残・決算発表予定**を自動で取りにいきます
(1銘柄1日1回まで)。空売り残高のカードのチェックボックスで切れます。

## 自動更新が動いているか分からないとき

更新表示に **取得回数**と**変化の有無**が出ます。「取得12回・変化なし」なら、
きちんと動いていて相場が動いていないだけです。
見出しには **取引時間中 / 取引時間外**も出ます — 止まって見える理由はたいていこれです。

ストリームは **受信件数**を表示します。「接続済み・配信なし」が続く場合、
その銘柄は配信対象外か、市場が閉じています。45秒無音だとそう表示します。

## 全期間を見るときの注意

**「全期間」は日足では返ってきません。** 提供元が長期の日足を持っていないためで、
週足か月足に丸められたデータが返ります。この場合ツールは自動的に足種の表示を実際の足に切り替え、
指標も**その足で計算し直します**(月足なら「25ヶ月線」と表示されます)。
「日足の全期間」を見せるふりをして月足の数字を出すことはしません。

## 1枚にまとめて書き出す

画面下の「1枚にまとめて書き出す」で、チャート・シグナル判定・指標の数値・直近20本を
**A4 1ページ**にまとめられます。印刷ダイアログで「PDFに保存」を選んでください。

**数値は画像ではなく文字として入ります。** AIにPDFを読ませたとき、チャートの見た目ではなく
実際の値(RSI、MACD、一目の転換/基準、空売り残高…)をそのまま読み取れます。
チャットに直接貼るなら「文字だけコピー」のほうが確実です。

## 何が同期されて、何がされないか

| | 同期 | 衝突したとき |
|---|---|---|
| お気に入り | する | 銘柄ごとに新しい操作が勝つ。**外した操作も伝わります** |
| 閲覧履歴 | する | 銘柄ごとに新しい閲覧時刻が勝つ |
| テーマ(明/暗) | する | 新しく変えたほうが勝つ |
| タブ構成・指標のオンオフ | 送るが、勝手には適用しない | 「別端末の画面を再現」を押したときだけ入れ替わります |
| 空売り・信用の蓄積データ | 「空売り・信用の蓄積データも含める」をオンにしたときだけ | 日付ごとに足し合わせ(消えません) |
| 画面の段組み(1列/2列/全画面) | **しない** | 見ている画面の性質なので、端末ごとの設定のままにしています |
| アラートの設定 | **しない** | 端末ごとの設定です(通知は開いている端末でしか鳴らないため) |
| 株価そのもの | **しない** | 取り直せるので入れていません(同期ファイルは1KB前後です) |

★を外したことも同期されます。片方の端末で外せば、もう片方も次の同期で消えます。
消したあとで同じ銘柄をもう一度★にすれば、そのまま両方に戻ります。

## iPhone を使う場合

**必ず共有ボタンから「ホーム画面に追加」してください。**
Safari は、ホーム画面に追加していないサイトの保存データを約7日で消すことがあります。
同期を設定してあれば全部は失われませんが、追加しておくほうが確実です。

## 手で持ち運ぶ場合(ネット接続なしでも可)

Google に接続したくないときは、同じ画面の下半分にある

- **ファイルに書き出す / 読み込む** … JSONファイルとして受け渡し
- **コードをコピー / 貼り付け** … 500文字程度の文字列。LINEやメールで送れます
- **同期先ファイルを選ぶ**(PCのみ) … iCloud Drive などの同期フォルダ内のファイルを覚えて、次からは1クリックで上書き

を使ってください。取り込み方は「合併(お気に入りを足す)」と「置き換え(タブ構成も再現)」から選べます。

## 動作を自分で確かめる

URL の末尾に `#selftest` を付けて開くと、**その端末・そのブラウザで実際に関数を動かした**
135件のテスト結果が出ます(指標の計算、タイムゾーン、XSS、通信先の許可リスト、保存と復元、端末間の同期)。
画面下の「動作テストを実行」ボタンでも同じことができます。

## 同期がおかしくなったとき

「同期できませんでした」が続き、**「同期ファイルを作り直す」**ボタンが出たときは、
Drive側のファイルが壊れています(別のプログラムに上書きされた、古いバックアップを戻した等)。
このボタンで削除して、その端末の内容から作り直せます。もう一方の端末にしか無いお気に入りは、
その端末が次に同期したときに戻ります。

## 注意

- 投資判断の助言ではありません。表示される「シグナル」は、指標の定義どおりの機械的な判定です
- 株価は Yahoo Finance / Stooq から、CORS中継サーバ経由で取得しています。
  中継サーバは第三者のものなので、**見ている銘柄コードはその運営者に見えます**。
  気になる場合は CSV 読み込みでお使いください
- チャートの縦線は**株式分割**(実線)と**配当落ち**(点線)です。「分割・配当」でオフにできます
- 空売り残高は JPX の日次ファイル(`YYYYMMDD_Short_Positions.xls`)から、
  信用残は日本証券金融の全銘柄CSV(`zandaka.csv`)、逆日歩は同じく `shina.csv` から取得します。
  取得できないときはファイル読み込み(.xls/.csv)に切り替えてください
- **JPXの公開は13ヶ月分**です。それ以前に報告されたまま一度も更新されていない残高は
  この集計に入らないので、何年も蓄積している投資情報サイトより小さく出ることがあります。
  「1年分」まで取り込むと差は縮みます
- 「このシグナルは効いているのか」の**「的中率」は、そのシグナルが主張した向きに動いた割合**です。
  売りシグナルなら「下がった割合」を出します(上がった割合ではありません)。
  v20以前は売りシグナルでも「上がった割合」を出していて、外れたときほど数字が高く見えていました
- ニュースは Google ニュースRSSを中継サーバー経由で読みます。混んでいると時間切れになります。
  もう一度押すか、表示される「Googleニュースで開く」からどうぞ

## v31 で直したこと

全体を機械的に検査して見つかった **40件** を直しました。重いものから。

**1. 自動取得が一度も動いていませんでした(致命的)**

`shortBusy` という変数がどこにも宣言されていませんでした。ファイル全体が
`"use strict"` なので、参照した瞬間に例外になります。しかもエラーは
`.catch(() => {})` に吸われるため、画面には何も出ません。
その結果 **空売り残高・日証金の貸借残・決算発表予定の自動取得は、
設定をONにしていても一度も実行されていませんでした。**
手動の「取得」ボタンも、表示はされるものの必ず失敗として扱われていました。

**2. 取得を押すと、貯めた空売り残高が消えることがありました(致命的)**

キャッシュを読む道が2つあり、片方(クローラ側)が古い形式を新しい形式に
直す処理を通っていませんでした。古い版で保存したデータがある銘柄で
「取得」を押すと、**蓄積した日数が新しく取った分だけに置き換わり**、
さらに割合が100分の1のまま「変換済み」の印を付けて保存されるため、
**あとから直せなくなっていました**。Googleドライブ同期の経路にも
同じ入口があり、そちらは同期のたびに起きていました。
いまは読み出し口をひとつにまとめてあります。

**3. 中継サーバーが「オープンプロキシ」になっていました**

許可ホストの判定が取得の *前* に一度きりで、転送の追跡は
ブラウザ任せ(`redirect: 'follow'`)でした。許可した相手が別のサイトへ
飛ばすだけで、**許可していないサイトの中身がそのまま返ります**。
1ホップずつ判定するようにしました。あわせて、
`ALLOW_ORIGIN` を設定してもブラウザ以外(curl など)は素通りだった点と、
`content-length` の無い応答でサイズ上限が効かなかった点も直しました。

**4. 週足・月足に、その日1日分だけのローソクが1本増えていました**

最新値を反映する処理が「日付」で比べていたため、週足・月足では
月の2日目以降・週の火曜以降に **同じ期間のローソクがもう1本**
足されていました。移動平均もRSIも1本ずれ、出来高の棒は1日分だけ立ちます。
足の単位で比べるようにしました。

**5. Apple や Microsoft を開くとJPXを取りに行っていました**

「日本株かどうか」の判定 `/^[0-9A-Z]{4}$/` が `AAPL` `MSFT` `META` `NVDA`
にも当たっていました。Appleを開いただけで、SheetJS(約900KB)と
JPXの日次ファイル最大10本(1本1〜3MB)と日証金のCSV(約3MB)を
取りに行き、**Appleのチャートに残高0%の線が引かれていました**。

**6. 逆に、285A のような新しいコードは引けませんでした**

2024年から発行されている「3桁+英字」のコードに `.T` が付かず、

**「なんで数日前のデータなの？」**

## v27 で直したこと

**指1本で時間軸を左右に動かせるようになりました**

これまで指1本は「値を読む」だけで、時間軸を動かすには**2本指**が必要でした。
気づきようがなく、片手では厳しい操作でした。

指1本が、そのときの動きに応じて3つに分かれます。

- **横になぞる → 時間軸が動く**
- 縦になぞる → これまでどおり画面のスクロール
- 指を止める → その足の値を読む(止めたあとは指を動かしても読み取りのまま)

(毎フレーム判定すると、少し斜めになぞったときに移動と読み取りがちらつきます)。

分からないままなのが良くないので、**2つの時間を分けて表示**するようにしました。

- **配信の遅れ** … 取得した時刻 − その値が付いた時刻。

- **取得から◯分** … いま − 最後に取りにいった時刻。

配信に無い場合は、足をさかのぼって前営業日の最後の足を使います
(直前の足は使いません)。

吹き出しでも分けて出します。分足では「前の足から」と「前日比」の両方が並びます。

ついでに **¥0.5000 → ¥0.5**。差額の桁数を差額自身の大きさではなく
**株価の桁**から決めるようにしました(¥1,382.5 の株なら小数1桁)。
ただし差が桁に対して小さすぎて 0 に丸まってしまう場合は桁を増やします
(159.441円の0.015円の動きが「0.0」になっていました)。

**比較チャートに左軸を足しました**

「比較の軸」で **指数(開始を100)** と **左軸に実数** を選べます。
実数にすると、左の軸が比較先の実際の値(ドル円なら159.44など)、
右の軸が株価になります。ローソク足も指標もそのままです。

- 実数の左軸は**比較が1本のときだけ**です。単位の違うものを1本の軸には載せられません。
  2本以上のときは指数に戻し、その理由を書きます
- 2つの軸の高さの合わせ方は**こちらで決めたもので、意味はありません**。
  そう画面に書いてあります。重なり方ではなく形をご覧ください

比較中の吹き出しが、四本値と指標を全部消して指数2行だけになっていたのも直しました。
比較の値は**追加**で並びます。

**2本指を縦に広げると株価の幅が広がります**

これまでピンチは横方向(期間)だけでした。縦に広げると価格の目盛りが伸び、
値動きが見やすくなります。

- 指の動きの**比率**で判定するので、横のピンチが価格の幅を変えたり、
  縦のピンチが期間を変えたりしません
- ダブルタップで両方とも元に戻ります
- タブごとに覚えるので、切り替えても戻りません

## v30 で直したこと

### 1. 4時間足・8時間足で Lorentzian が出なかった

**東京市場の立会いは5時間**しかありません。1時間足が1日6本なので、
それをまとめた**4時間足は1日2本、8時間足は1日1本**にしかなりません。
つまり同じ「1ヶ月」でも、足種によって本数がまるで違います。

| 足種 | 1ヶ月 | 3ヶ月 | 6ヶ月 | 1年 | 2年 |
|---|---|---|---|---|---|
| 15分足 | 約570本 | — | — | — | — |
| 4時間足 | **44本** | 130本 | 260本 | 490本 | 980本 |
| 8時間足 | — | **65本** | 130本 | 245本 | 490本 |

Lorentzian は**最初の60本を学習に使う**ので、44本では1本も予測が出ません。
そして足種を変えたとき、これまでは**同じ「1ヶ月」を引き継いで**いました。
15分足の1ヶ月から4時間足に切り替えると、ちょうどこの44本の状態に着地します。
**だから15分足では出て、4時間足以降は出ませんでした。**

3つ直しました。

- **足種を変えたときは「同じ日数」ではなく「同じくらいの本数」を引き継ぐ**ようにしました。
  15分足の1ヶ月(570本)から4時間足なら、1ヶ月ではなく**1年**(490本)を選びます。
- **指標が引けない短さは自動では選ばない**ようにしました。一目均衡表の先行スパンBは
  52本＋26本先行で最低78本必要です。これに満たない期間へは自動で飛びません。
  (ボタンは残っているので、自分で選ぶことはできます)
- **それでも本数が足りないときは、パネルの中に理由を書く**ようにしました。
  「44本では予測できません(60本以上必要)」「4時間足は1日約2本です。期間を長くしてください」。
  **空のパネルは故障に見えます。**何を待っているのか画面に書くべきでした。

ついでに、同じ理由で**週足の1年(52本)・月足の2年(24本)も一目均衡表が引けていません**
でした。こちらも自動では選ばれなくなります。

案内の文面も直しました。これまでは「期間を5年か全期間にしてください」と出ていましたが、
**4時間足と8時間足には5年も全期間もありません**(1時間足のデータ上限が約2年のため)。
いま押せるボタンだけを案内します。

### 2. 前日比がまだおかしかった

前回 `chartPreviousClose` をやめたのですが、まだ足りませんでした。
足りなかったのは**「1日1本しかない系列を分足として表示している場合」**です。
このとき「前の市場日」を探して1本余計に遡り、**前々日の終値**と比べていました。

いまは、**その日の足が複数あるときだけ**チャートから前日終値を割り出し、
そうでないときは取得元が申告した前日終値を使います。

|  | 使う値 |
|---|---|
| 15分足で今日の足が26本ある | チャート上の**前の市場日の最後の終値** |
| 1日分しか入っていない | 取得元の `previousClose` |
| 日足・週足・月足 | **1本前の終値** |
| 2年分の範囲の先頭より前の値 | **使いません**(これが +19.76% の原因でした) |

### 3. 更新しても、その回は前の版が出ていました

オフライン用のキャッシュが、本体のHTMLまで
**「まずキャッシュを返して、裏で新しいものを取ってくる」**方式でした。
つまり新しい版を置いても、**開いた回は前の版**が表示され、
もう一度開いて初めて新しくなります。

直したはずのものが直っていない、人によって・時によって挙動が違う、
という見え方の一因です。本体だけは**先にネットワークを見る**ようにしました
(3秒で諦めてキャッシュに切り替えるので、圏外でも今までどおり開きます)。

`Cache-Control: max-age=600` を返すサーバー(GitHub Pages がそうです)では、
ネットワークを見に行っても**ブラウザ自身のキャッシュ**が10分間は古い版を
返します。そこも越えるようにしてあります。

**この版に上げるときだけ、1回だけ手動で更新が必要です。**
古いキャッシュが今のルールで動いているためです。スマホなら、
ページを開いて**下に引っ張って再読み込み**を2回してください。

## v29 で直したこと

「動く時と動かない時がある」を追いかけて、操作まわりを一通り見直しました。
原因は1つではなく、**指を無視する経路が7つ**ありました。

**1. 区切り線がスワイプを飲み込んでいました(いちばん大きい原因)**

パネルの高さを変える当たり判定が、タッチのとき **上下22px × パネルの幅いっぱい**で、
しかもパネルごとに2本の線に付いていました。74pxのサブパネルなら**その6割**が
「高さ変更」になり、そこを横になぞっても時間軸は動きません。
指の位置しだいで動いたり動かなかったりする、というのはこれです。

タッチでは**描いてある取っ手(右端の横棒)の上だけ**を当たり判定にしました。
それ以外は全部チャートなので、どこをなぞっても時間軸が動きます。
マウスは今までどおり線全体で掴めます(カーソルが変わるので狙えるため)。

**2. タップした値がすぐ消えていました**

指を離すとブラウザはそのポインタを「消滅」させ、直後に離脱イベントを出します。
それが、タップで出したばかりの値を**描画される前に**消していました。
0.24秒以上押さえていれば別経路で出るので、
「速くタップすると出ない・長く押すと出る」という分かりにくい挙動でした。
タッチの離脱では消さないようにしました(マウスは今までどおり)。

**3. 別の場所に置いた指がピンチ扱いされていました**

片手持ちで親指が画面のどこかに触れていると、それを2本目の指と数えて
「ピンチ」と判定し、スワイプが拡大縮小になったり固まったりしていました。
チャートの上に乗っている指だけを数えます。

**4. ピンチのあと残った指が死んでいました**

2本指で操作して1本だけ離すと、残った指はどのジェスチャーにも属さず、
一度離して置き直すまで何をしても反応しませんでした。引き取るようにしました。

**5. ピンチ状態が取り残されることがありました**

通知や他アプリへの切り替えでジェスチャーが中断されると「ピンチ中」のまま残り、
1本指の操作が全部素通りして、**再読み込み以外に戻す方法がありません**でした。
中断・離脱・タブ非表示のすべてで解除します。

**6. 足種を変えると期間が全期間に飛んでいました**

1時間足の1ヶ月から日足に変えると、いきなり全期間になっていました。
選べない期間になったときの逃げ道が「一覧の最後＝いちばん長いもの」だったためです。
**いちばん近い長さ**を選ぶようにしました(1ヶ月からなら3ヶ月)。

**7. 重い指標の計算が失敗すると画面全体が固まっていました**

Lorentzianなど計算に時間のかかる指標は、計算中は「取得中…」にして
ボタンを止めます。その計算が失敗すると**元に戻す処理まで届かず**、
再読み込みするまで「分析」が押せないままでした。
失敗してもボタンは戻し、その指標だけ切って、何が起きたか表示します。
